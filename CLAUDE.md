## Project Overview

This is a Magento 2.4.4 Community Edition project with custom modules and themes. The application runs in a Dockerized environment with multiple services including MySQL, Redis, Elasticsearch, RabbitMQ, and Varnish.

## Development Commands

### Docker Commands
```bash
# Start containers (Linux)
docker-compose -f docker-compose.dev.linux.yml up -d

# Start containers (macOS)
docker-compose -f docker-compose.dev.mac.yml up -d

# Execute commands in PHP container
docker-compose exec phpfpm [command]
```

### Magento CLI Commands
All Magento commands should be run inside the phpfpm container:

```bash
# Clear cache
docker-compose exec phpfpm bin/magento cache:clean
docker-compose exec phpfpm bin/magento cache:flush

# Reindex
docker-compose exec phpfpm bin/magento indexer:reindex

# Deploy static content
docker-compose exec phpfpm bin/magento setup:static-content:deploy -f

# Compile dependency injection
docker-compose exec phpfpm bin/magento setup:di:compile

# Database upgrade (after module changes)
docker-compose exec phpfpm bin/magento setup:upgrade

# Enable/disable modules
docker-compose exec phpfpm bin/magento module:enable [module_name]
docker-compose exec phpfpm bin/magento module:disable [module_name]

# Developer mode
docker-compose exec phpfpm bin/magento deploy:mode:set developer

# Production mode
docker-compose exec phpfpm bin/magento deploy:mode:set production
```

## Architecture

### Custom Modules Location
All custom modules are located in `app/code/`:
- **Macademy/Blog**: Blog functionality with posts, repository pattern, REST API
- **Macademy/FreeShippingPromo**: Free shipping promotional features
- **Macademy/JsFun**: JavaScript functionality and examples
- **Macademy/ProductCompare**: Product comparison features
- **Macademyy/InventoryFulfillment**: Inventory fulfillment features
- **Juno/Theme**: Custom theme

### Module Structure
Each module follows Magento 2 structure:
- `etc/`: Configuration files (module.xml, di.xml, routes.xml, db_schema.xml)
- `Model/`: Data models and business logic
- `Controller/`: Frontend controllers
- `Api/`: Service contracts and interfaces
- `view/`: Layout XML and templates
- `Setup/`: Database patches and installation scripts

### Key Patterns
- **Repository Pattern**: Used for data persistence (e.g., PostRepository)
- **Service Contracts**: API interfaces in Api/ folders
- **Dependency Injection**: Configured via di.xml files
- **Database Schema**: Declarative schema in db_schema.xml
- **Frontend Routes**: Defined in etc/frontend/routes.xml

### Database
- Main table for blog: `macademy_blog_post`
- Database host in Docker: `db`
- Database name: `magento`

### Service URLs
- Frontend: http://localhost:8080
- Admin: http://localhost:8080/admin
- Adminer (DB management): http://localhost:8090
- MailHog (email testing): http://localhost:8025
- Kibana: http://localhost:5601

## Development Workflow

1. Make changes to module code
2. Clear cache: `docker-compose exec phpfpm bin/magento cache:clean`
3. If database changes: `docker-compose exec phpfpm bin/magento setup:upgrade`
4. If dependency changes: `docker-compose exec phpfpm bin/magento setup:di:compile`
5. For frontend changes: `docker-compose exec phpfpm bin/magento setup:static-content:deploy -f`
6. Test changes in browser

## Code Standards

- Follow PSR-2 coding standards
- Use PHP CS Fixer configuration from `.php-cs-fixer.dist.php`
- All custom module classes should use strict types: `declare(strict_types=1)`
- Follow Magento 2 best practices for dependency injection
- Use repository pattern for data access
- Implement service contracts (interfaces) for public APIs
